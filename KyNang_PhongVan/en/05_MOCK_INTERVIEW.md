# 5. Mock Interview

Practice by answering the questions below out loud, timed. Includes how to handle hard questions.

## A typical session (fresher/junior)

1. **Self-introduction** (→ see file 01).
2. **Deep-dive on a project**: "Tell me about [project X]" → a 2-minute pitch (see each project's file 00), then technical probing.
3. **Foundational technical questions** (→ see `LuyenTap_KyThuat/`).
4. **Behavioral questions** (→ STAR, file 02).
5. **(Maybe) coding/whiteboard** (→ `LuyenTap_KyThuat/05`).
6. **You ask back** (→ file 03).

## Practice question bank (answer out loud, timed ~1–2 min each)

**Opening**
- Introduce yourself in 60 seconds.
- Why this role / this company?
- What project are you most proud of, and why?

**Project deep-dive (pick one project and practice the whole chain)**
- What problem does it solve? Who's it for?
- What's the overall architecture? Describe the main data flow.
- Which technical decision are you most proud of? Why that over alternatives?
- The hardest challenge? How did you solve it?
- Known limitations? What would you improve with more time?
- How did you test it? How do you know it's correct?

**Behavioral**
- Tell me about a very hard bug.
- A time you self-taught a new tech quickly.
- A time you had to trade off between two options.

## Handling HARD questions

**"I don't know this one."**
> Don't fake it. Say: "I haven't done that part, but I think the approach would be… [reason out loud]. I'd look up [source] to be sure." → shows reasoning + honesty.

**Repeated "why" probing.**
> This is a GOOD sign (they're interested). Give the real reason; if it's a trade-off, name both sides: "I chose X for A, at the cost of B; here A matters more."

**Pointed out a flaw in your project.**
> Don't get defensive. Acknowledge: "Right, that's a limitation. If I redid it I'd… / I noted it in the limitations section." → more mature than arguing.

**Vague question ("What do you think about…").**
> Clarify the scope first: "Do you mean [A] or [B]?" → avoids answering off-topic.

**Lost your train of thought (rambling).**
> Pause, breathe: "Let me summarize the key point:…" → pull back to the core.

## Pre-interview checklist
- [ ] 30s + 90s self-intro (file 01).
- [ ] 2-minute pitch for your 2 strongest projects.
- [ ] 3 STAR stories (file 02).
- [ ] Can explain 2 technical decisions + reasons, per strong project.
- [ ] Can name a limitation + fix per project.
- [ ] 4–6 reverse questions (file 03).
- [ ] Review relevant technical fundamentals (`LuyenTap_KyThuat/`).
- [ ] Sleep well; test mic/camera if remote.

> 💡 Practicing with **someone playing the interviewer** (or recording yourself) is far more effective than silent reading. Replaying reveals rambling/stumbling to fix.
